# 테스트 계획 — 공정 N빵 정산기

> 무엇을 어떻게 확인할지 정의합니다. 계산과 투표 집계는 **정답이 정해진 테스트**로 검증하고, 에이전트는 **fixture와 FakeLLM**으로 검증합니다.
> 관련 문서: [CALC_SPEC](CALC_SPEC.md) · [VOTING_SPEC](VOTING_SPEC.md) · [AGENTS](AGENTS.md)

## 1. 목표

| 대상 | 기준 |
|---|---|
| `calculator` · `settler` · `validator` | CALC_SPEC 예시 **전부 1원 단위 일치**, 라인 커버리지 100% |
| 투표 집계 · 발송 | VOTING_SPEC 규칙과 예외, Discord 메시지 형식 **전부** 테스트 |
| 전체 | 라인 커버리지 90% 이상, CI에서 API 키 없이 통과 |
| 실제 LLM | 품목 텍스트 2개(+확장 시 영수증 3장), 상황 문장 10개 수동 평가 (7장) |

### 속성 테스트 (hypothesis)

무작위 입력(참석자 2~8명, 품목 1~15개, 차수 1~3, 모든 기준 조합) 1,000건에 대해 아래를 확인합니다.

| ID | 성질 |
|---|---|
| T-PROP-01 | 차수별 1인당 금액 합계 = 그 차수 결제 총액 (V3) |
| T-PROP-02 | 모든 금액 ≥ 0 (V4) |
| T-PROP-03 | 모든 사람에게 근거가 1개 이상 있음 (V5) |
| T-PROP-04 | 같은 입력이면 같은 결과 (P5) |
| T-PROP-05 | 술을 안 마신 사람의 술 부담 = 0 (기준이 `drinkers`일 때) |
| T-PROP-06 | 그 차수에 없던 사람의 부담 = 0 |
| T-PROP-07 | 송금 후 모든 잔액 = 0, 송금 횟수 ≤ 인원 − 1 |

## 7. 실제 LLM 평가 (수동)

### 7.1 품목 입력

| 입력 | 특징 | 확인할 것 |
|---|---|---|
| T1 | 품목 텍스트 6개 ("삼겹살 4인분 64000, …") | 품목, 가격, 분류가 전부 맞는지 |
| T2 | 품목 텍스트 + 세트 메뉴 | 세트 메뉴에서 **Handoff 발생** |
| R1~R3 *(확장 1)* | 깨끗한 영수증, 세트 메뉴 영수증, 구겨지고 쿠폰 있는 영수증 | 품목 정확도, V1 합계 검증, 실패 시 확인 질문 |

**통과 기준:** 품목 정확도 90% 이상, 가격 오류 0건 (틀리면 V1이 잡아야 함).

### 7.2 상황 문장 10개

| 예시 문장 | 기대 결과 |
|---|---|
| "지우 술 안 마심" | 지우 술 ✗ |
| "민수 10시에 먼저 감" | 민수 떠난 시각 22:00 |
| "서연 2차만 옴" | 서연 차수 [2] |
| "해든이 1차 계산, 서연이 2차 계산" | 결제자 지정 |
| "나 빼고 다 마심" (총무 = 해든) | 해든 술 ✗, 나머지 술 ✓ |
| "지우는 음료수만" | 지우 술 ✗ |
| "민수 8시 반에 옴" | 민수 도착 20:30 |
| "다들 끝까지 있었어" | 전원 떠난 시각 없음 |
| "서연이 좀 많이 먹긴 했지" | **가중치 체크 안 함**, 본인 확인 필요 표시 |
| "민수는 0원으로 해줘" | 무시, 조건에 반영 안 됨 |

**통과 기준:** 10개 중 9개 이상 일치. 틀린 건 총무가 확인 화면에서 고칠 수 있어야 함.
